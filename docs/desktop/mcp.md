# Local MCP

**Local MCP** ("Use nvoke in Claude and Cursor" on Account): Claude Desktop, Claude Code and Cursor get the MCP tools through the app's own sign-in, with no API key. Main listens on a local pipe (`\\.\pipe\nvoke-mcp-<12 hex of sha256(userData)>` on Windows, `userData/mcp.sock` with mode 0600 elsewhere) and runs one MCP session per connection (`@modelcontextprotocol/sdk`, newline delimited JSON like stdio). Tools and instructions are `MCP_TOOLS` and `MCP_INSTRUCTIONS` from the catalog, run by `runMcpTool` (`packages/shared/src/mcp.ts`, shared with `POST /mcp`) through `AuthSession.api`, so the device token never leaves main. Signed out, every tool answers an error asking the user to sign in. Clients start `mcp-launcher.js` (built beside the main bundle, unpacked from the asar) with the app binary in Node mode: `ELECTRON_RUN_AS_NODE=1 nvoke mcp-launcher.js <pipe> [app args]`. It relays stdio to the pipe; when nvoke is not running it starts it with `--hidden` and waits up to 20 seconds. Account shows the clients connected now (from `clientInfo` at initialize, pushed on `mcp:clients-changed`), an Add to Claude Desktop button, the `claude mcp add nvoke --scope user ...` line for Claude Code and the JSON for Cursor's `~/.cursor/mcp.json`. Add to Claude Desktop asks in a native dialog, then sets `mcpServers.nvoke` in `claude_desktop_config.json` (`%APPDATA%\Claude`, the Store build's package folder when it exists, `~/Library/Application Support/Claude` or `~/.config/Claude`), keeps every other key, writes through a temp file and refuses a file that is not a JSON object. Without Claude Desktop's folder the button becomes Get Claude Desktop. Code: `apps/desktop/src/main/mcp`, `src/main/mcp-launcher.ts`, `components/LocalMcp.tsx`.
