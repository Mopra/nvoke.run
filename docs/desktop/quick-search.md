# Quick search

**Quick search**: a global shortcut (default Ctrl+Shift+Space on Windows and Linux, Cmd+Shift+Space on macOS, changeable on Account) opens a small frameless glass window, centered on the display under the pointer, over whatever app is in front. It is the command bar again (`Commands` in `CommandBar.tsx`, loaded by the same renderer on `#/quick`): type to jump to a search or run an action, and screens open in the main window. When the clipboard holds one domain, URL or email address at the moment the window opens, the first row is "Find contacts at acme.com" and Enter runs a one-domain search of kind `domains` (limit 1); the window then lists the addresses as they arrive, each with a copy button (invalid ones left out). The clipboard is read once, in main (`src/main/clipboard-lookup.ts`), when the window is shown, never in the background, and only a clean domain, URL or email passes (prose, lists and long text are ignored); the quick window gets the result with `quick:shown`. Above it sits "Who runs this site" with the domain of the browser tab that was in front when the shortcut was pressed, which runs the same one-domain search. The tab is read only on the shortcut, in main (`src/main/front-tab.ts`), and arrives a moment after the window shows with `quick:front-tab`; when the tab and the clipboard name the same site there is one row. Windows: a short PowerShell script (UI Automation, part of Windows, nothing installed) walks the top level windows front to back, skips nvoke's own and topmost ones, and when the first is Chrome, Edge, Firefox or Brave reads its address bar (about 0.7 s). macOS: the window list names the app in front without any permission; for Safari, Chrome or Arc AppleScript returns the front tab's URL. That needs the user's Automation permission, so the first time per browser the row says macOS will ask, and Enter (`quick:read-front-tab`) shows the system prompt (text from `NSAppleEventsUsageDescription` in `electron-builder.yml`) while the window stays up, then starts the search. Browsers already asked are kept as `automationAsked` in `userData/desktop-settings.json` and read without asking; a refusal turns the row into a pointer to System Settings, Privacy & Security, Automation. Other apps, browser pages (`chrome://`, `about:`, files) and Linux give no row. Typing text adds rows that start a search on Enter: "dentists in Aarhus" (or "near") is a local search, anything else a web search, and "Sonar: ..." starts a Sonar (`icp`) search of up to 1000 companies that keeps finding new leads. The plain words row comes first when the text reads like a description (docs/desktop/people.md). The window then shows the search's progress, and Open in nvoke (Enter) brings up the main window on it. Esc, a click elsewhere or the shortcut again hides it and the previous app keeps focus (macOS: nvoke hides itself). Signed out it offers Open nvoke. The shortcut works while nvoke sits in the tray. Registration is `globalShortcut` in `src/main/quick-window.ts`; if another app holds the shortcut, the old one stays and Account shows the clash. The accelerator is validated in `src/ipc/accelerator.ts` (modifier plus key) and kept as `hotkey` in `userData/desktop-settings.json`. Channels: `desktop:set-hotkey`, `quick:hide`, `quick:open-in-main` (route hash), `quick:set-height`, `quick:shown`, `quick:front-tab`, `quick:read-front-tab`; the quick channels only answer the quick window.
