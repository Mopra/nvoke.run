# CSV drop

**CSV drop.** Drop a .csv, .tsv or .txt on the window (XLSX is refused with a hint to save as CSV UTF-8; up to 5 MB): while the file is over the window a glass target says so, then a dialog names the file, lets the user pick the column (guessed: cells that read as domains first, then a header like website or domain, then company or name) and shows the domains and names it found, with a country line when there are names. "Find contacts" starts a `domains` search with the unique items of that column, cut at the plan's search limit (the dialog says how many were left out). The renderer reads the file's text and parses it (quotes, `,` `;` or tab, header row detected). Its path comes from `webUtils.getPathForFile` in the preload (`files.pathFor`). When the search is `done`, the renderer fetches every company and sends the original's path and the CSV to main (`files:save-enriched`). Main accepts an absolute path to an existing .csv, .tsv or .txt file and a CSV of at most 16 MB, and writes `<name>.nvoke.csv` in the same folder itself (replacing an earlier copy, never `.nvoke.nvoke.csv`). The copy is the original columns plus `domain`, `email`, `kind` and `verification` (prefixed `nvoke_` when the file already has that column): one row per email, a row without a match keeps its cells with blank new ones, formulas in new cells are defused. A toast says how many companies have a valid address and offers Show in folder (`files:reveal`, only for `.nvoke.csv` files). The search shows in Searches like any other. Jobs are held by the renderer: quitting the app before the search finishes means no copy (the search and its export remain). In a plain browser (mock) the copy downloads instead.
