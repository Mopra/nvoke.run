# Local copy

**Local copy**: the main process keeps the signed-in user's searches, companies and checked emails in SQLite (`node:sqlite`, which Electron ships) at `userData/leads.sqlite` (`apps/desktop/src/main/local`). A finished search's results open from it at once, and text search and the verification, kind and decision maker filters run on it in milliseconds over 50k+ companies, with the same semantics as `GET /v1/searches/:id/companies` (decision makers is desktop only, docs/desktop/people.md). Companies are stored whole, so names, titles, found via, confidence and fit survive offline. A running search reads the API live. Sync runs in the background: `GET /v1/searches` every minute (every 10 seconds while a search runs), then every page of companies for each search that finished or changed, was opened, or was last fetched 6 hours ago, at most 8 searches a pass. Offline, the searches list, search details and results come from the copy, and Searches and the results dock say "Offline, synced 42 min ago". No new API: the copy is built from the existing routes. The renderer reads it through `window.nvoke.local` (`src/ipc/features/local.ts`). The command bar (Cmd or Ctrl K, and the quick window) searches it too: from two characters it lists up to six companies from every synced search whose name, domain or an address contains the text, newest search first, each with the matching address (else the first one, else the domain) and its search, and how many more matched. Enter opens that search with the text filter set to the company's domain. It runs in main as one query over all companies (`local:find`, `LocalStore.findCompanies`), offline too.
