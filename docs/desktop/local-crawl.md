# Local render crawl

The VPS crawl stays the crawl. Two kinds of site defeat it: sites that refuse datacenter addresses (`refused`) and sites that render everything with JavaScript (`js_only`). The desktop app can read those from the user's own computer: Chromium is already in the app, and the user's connection is not a datacenter. Off by default; the user turns it on per computer. Verification and billing stay on the server.

- **Same rules as the bot.** robots.txt for `nvokebot` on every page and every redirect (2xx obeyed, 4xx allows, 5xx or unreachable disallows), the `nvokebot/1.0 (+https://nvoke.run/bot)` user agent and nothing that pretends to be a regular browser, at most one page per second per host (longer for a robots.txt Crawl-delay), at most 8 pages per company. It never types into a form, never passes a login and never solves a CAPTCHA: a page with a password field or a challenge (reCAPTCHA, hCaptcha, Turnstile, "Just a moment...") is not read, and on the homepage that ends the company as `blocked`. Platform and logged-in sites (LinkedIn, Facebook, marketplaces: `isPlatformDomain`) are never claimed or opened.
- **Claim.** `POST /v1/local-crawl/claim` with `{ max? }` (1 to 5, default 3) returns `{ tasks: [{ companyId, searchId, domain, website, reason }] }`, where `reason` is `refused` or `js_only`. It picks companies from the caller's own searches made in the last 30 days and not canceled, newest first, whose crawl ended `refused` or `js_only` and that have no local result yet, skipping suppressed and platform domains. Each claim is a lease of 10 minutes (`local_claimed_until`); a lease that runs out is claimable again, twice in all (`local_attempts`), then the company settles as local `failed`. Nothing is claimed while the user's allowance is used up.
- **Results.** `POST /v1/local-crawl/results` with `{ companyId, outcome, emails, pages }`: `outcome` is `done`, `failed` or `blocked`, `emails` at most 50 of `{ address, sourceUrl }`, `pages` how many pages were read (0 to 8). 404 `not_found` for a company that is not the caller's, 409 `not_claimed` when it holds no live claim. The server trusts nothing it is sent: every address goes through the server's own acceptance (`acceptAddress`), classification and own-domain rule (`selectForCompany` with the company's domain), a `sourceUrl` must be an http(s) URL, and suppressed addresses are dropped. The rest go into that search's `emails` and get a verify job like any crawl, so the user pays only for valid ones and `lead.ready` fires when they settle, even after the search is `done`. Local results never enter the shared cache (`domains`, `domain_emails`): they came from a client, so they stay in the user's own search. Returns `{ stored }`.
- **When the desktop works.** Only while signed in, with the setting on, not on battery, and while the computer is idle for 2 minutes or locked (`powerMonitor.getSystemIdleState`). It checks every 2 minutes, claims a few companies, reads them one at a time and goes quiet when the user comes back (it finishes the company it is on). Code: `apps/desktop/src/main/local-crawl/`.
- **The hidden window.** One `BrowserWindow` that is never shown: `sandbox`, `contextIsolation`, no `nodeIntegration`, no preload, images off, in its own in-memory session (`nvoke-local-crawl`, no `persist:`) whose cookies, storage and cache are cleared after every company. Every permission request is denied, downloads, HTTP auth and client certificates are refused, `window.open` is refused, JavaScript dialogs are silenced (through the DevTools protocol, before page scripts run), and images, media, fonts, plugins, frames and websockets are not loaded. Requests to `localhost`, `.local`, private, loopback and link-local addresses are canceled, and a page's host must resolve to a public address before it loads, so a site cannot point the user's browser at their own network. Each page gets 20 seconds to load and 1.5 seconds more for scripts to render; then the rendered DOM is read from an isolated world (the page's own scripts cannot change what is read), capped at 2 MB.
- **Extraction.** The rendered HTML goes through the same extractor as the server (`@nvoke/shared/crawl`: `extractEmails`, `pickLikelyPages`, `selectForCompany`). The homepage first, then the likely pages it links to, or the guessed paths (`/contact`, `/kontakt`, `/about`) when it links to none. Only addresses and the URL each was found on leave the computer. Never page content, HTML or screenshots.
- **Visible.** Account has the switch. Results show a refused or JS-only company as waiting for this computer (or suggest the switch), "Reading from this computer" while it is claimed, and the addresses once they are in.
