# Start from your website

**Start from your website.** New search opens on one field: "Start from `yourcompany.com`" and a primary Read my site button. The renderer sends the site to `POST /v1/site-profile` through `window.nvoke.request` (no new IPC channel; the bridge has no request timeout, so the 10 to 30 second call runs to the end). While it runs the aura rises and one calm line per phase replaces the form, timed from the moment the build started: "Reading acme.dk", the about, pricing and services pages, "Working out who buys from you", "Planning searches that find them". An indeterminate bar, no percentages. The build is a React Query mutation with a fixed key, so leaving New search and coming back still shows it, and the result lands in the cache either way.

**Suggestions.** With a profile on the account (`GET /v1/site-profile`, key `['site-profile']`, 404 reads as none), New search opens straight on it: the domain and when it was read, the name in display type, the summary and who it sells to, then the 3 to 6 suggested searches. Each row shows the search title (`searchTitle`, the same as the Searches list), its kind and size, the `why` line and a Start button. Start sends the suggestion's `search` to `POST /v1/searches` through `useStartSearch` (`lib/start-search.ts`), the same path the manual form uses: the search goes into the cached list, a toast names it and the app replaces New search with its results. Read again rebuilds from the stored website; Read another site shows the field again with a way back to the suggestions.

**Edit.** Edit swaps the readout for every profile field inline: name, what you do, what you sell, who buys it, proof (one per line), your words (comma separated), language (two letters) and the country it sells in most (the CountryPicker, any country is `null`). Save checks the server's limits first and sends one `PATCH /v1/site-profile` with only the fields that changed. Suggestions stay as they were built.

**By hand.** Every state of the step has a "Set up a search by hand" link to `#/new?kind=local`, the manual tabs form as it was, which has a "Start from your website" link back. Plain `#/new` (the New search button, Cmd+N, the tray) opens the website step; a kind in the route opens the manual form on that tab, so the command bar's "Paste a list of companies" and the other search entries land on their tab. CSV drop, grab, the quick window and the inbox start searches directly and never pass through New search. When the account has no searches, the Searches empty state is "Start from your website" with one Read my site button.

**Errors.** One short line next to the button, with the manual link below it: `site_unreadable` by `detail` (`unreachable`: the site did not answer; `blocked`: "robots.txt keeps us out of acme.dk."; `refused`; `js_only`; `empty`; `not_allowed`: private or local address), `rate_limited` (10 reads a day), `ai_unavailable`, `invalid_request`, offline. Main passes the server's `detail` through the bridge only when it is a short lowercase code. A field that is not a public host name (no dot, `localhost`, an IP address, spaces) is refused before the request.

**Code.** `lib/site-profile.ts` holds the pure parts with tests next to it: `parseWebsite`, the build phases, the error lines, the suggestion caption and the edit form as data (`profileToDraft`, `draftToUpdate`). The screen is `screens/StartFromWebsite.tsx`, routed from `NewSearchScreen.tsx`. The mock (`VITE_MOCK=1`) answers all three routes: a plausible clinic web studio profile named after the domain with five suggestions across local, web, launches and domains, about five seconds per build, kept in `localStorage` (`nvoke.mock.site-profile`), and any site under `.invalid` fails with `site_unreadable`/`unreachable`. Capture shots: `03a-website-step` to `03e-website-error` (`src/main/capture/shots/site-profile.ts`).
