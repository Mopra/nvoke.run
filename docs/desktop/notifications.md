# Drop notifications

**Drop notifications**: main polls `GET /v1/searches` every minute while signed in (no new endpoint). A finished `drop` search with at least one valid email raises a native notification titled with the drop's name, "14 new launches, 9 valid emails", once per search; clicking it focuses the window and opens that search. The count of valid emails in finished drop searches not yet opened is the dock badge on macOS, an overlay icon with that number on the Windows taskbar button (drawn in main, 99 at most) and the launcher count on Linux. Opening a search (by hand or by the click) clears its share. The first poll after signing in only records what exists, so old deliveries never badge or notify. No toast shows while the nvoke window is focused; otherwise the OS applies Focus (macOS) or Focus Assist (Windows). State (the setting, announced and seen search ids) lives in `userData/notifications.json` and is reset on sign out. Channels: `notifications:get-settings`, `notifications:set-enabled` (boolean, validated), `notifications:mark-seen` (uuid, validated), and the push `notifications:open-search`.
