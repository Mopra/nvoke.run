# Source costs

Brave Search bills every request, while users pay only for valid emails. A web search that finds nothing still costs requests, so the find job keeps that cost down:

- **Stop early.** The adapter fetches one page (20 results) at a time and the find job stops pulling as soon as the search has `limit` companies, so a search never fetches pages it does not use. At most 10 pages per search.
- **Paid web search providers.** Web search has a primary paid provider (`WEB_SEARCH_PROVIDER`, `brave` by default, or `serper` for Google results from serper.dev) and an optional paid fallback (`WEB_SEARCH_FALLBACK`). The fallback answers when the primary refuses us (key, credit or quota), fails, is paused in `source_pauses`, or is past its monthly budget; the free search (Mwmbl, `FREE_SEARCH`) stays the last fallback behind both, and searches are refused as paused only when every configured provider is. Without a fallback and with Brave as primary, Brave answers alone, as before. A page is always 20 results: one Brave request, or two Serper requests of 10. Both providers share `web_search_cache` under the same query, country and page keys, with the same retention. Each paid request still counts in `searches.source_requests`; with Serper configured, each provider's requests are also counted per UTC month in `web_search_usage`, priced at `BRAVE_COST_PER_1000_USD` or `SERPER_COST_PER_1000_USD`, and alerted at 80% and 100% of `BRAVE_MONTHLY_BUDGET_USD` or `SERPER_MONTHLY_BUDGET_USD`, naming the provider. A refusing provider is paused under its own name (`nv sources resume serper`).
- **Cache.** Every page is stored in `web_search_cache` by normalized query (trimmed, lowercased, single spaced), country and page, and reused by any search for 7 days (`RETENTION.webSearchCacheDays`). A cache read or write that fails never fails the search.
- **Rate.** `BRAVE_REQUESTS_PER_SECOND` (default 1, the free plan) sets the shared rate limit, with a tenth of headroom. `web`, `domains`, `local` and `icp` searches share one client, so one limit.
- **Refusals.** A 429 whose spent window resets within 5 seconds is waited out (3 tries). A 429 for a long window (monthly quota, the usage limit set in the Brave dashboard) and any 401, 402 or 403 raise `SourceUnavailableError`: Brave is paused in `source_pauses` for 10 minutes, the operator gets an alert and the free search below answers in its place for the rest of the pause (pages Brave answered before still come from the cache). Only when the free search is off or refuses us too does the search fail with `source_unavailable` (companies already found keep crawling). While Brave is paused and the free search is off or paused too (`free_search` in `source_pauses`), `POST /v1/searches` refuses web searches with 503 `source_unavailable` and the desktop says web search is paused on our side. When the pause runs out the next web search tries Brave again, so it recovers on its own once the limit is raised. `cli sources resume brave --prod` ends it at once.
- **Free search** (`src/leads/sources/free-search.ts`, `FREE_SEARCH`). Mwmbl's public search API (`api.mwmbl.org`, no account) behind the Brave client's interface, so `web`, `domains`, `local` and `icp` use it unchanged. `fallback` (default; the owner accepted Mwmbl's terms, whose data licence is CC BY-NC-SA, on 2026-10-18) uses it when Brave refuses us, is paused or has no key; `off` is Brave alone; `first` asks it before Brave and pays Brave only when it finds nothing. Brave operators (`site:`, `OR`, quotes, `-word`) are dropped and results are held to the `site:` hosts; the country's English name joins the words and, when that finds nothing, the query is tried once without it (or without its last word). One page holds all its results (up to about 60). One request every `FREE_SEARCH_INTERVAL_MS` (default 3 seconds) as `nvokebot`, pages cached in `web_search_cache` under the country key `mwmbl:<country>` and free on reuse; an empty answer is kept for its UTC day only (`mwmbl:<country>:empty:<date>`). Its requests are never reported as `source_requests` or `source_cache_hits`, so Brave cost stays honest. A 403, 429 or 503, or a body that is not JSON and looks like a challenge page, stops it for 30 minutes (`free_search` in `source_pauses`) and is never worked around; a timeout or server error skips that query, and five in a row count as a refusal. While it answers for Brave the stage is `fallback` and the note says so ("Our main web search is unavailable right now, so nvoke is searching with Mwmbl, a free search engine. Expect fewer results"). Its index is small: good for common English phrases, thin or empty for local and long queries. Tried and left out on 2026-10-18: DuckDuckGo's HTML endpoint (a puzzle challenge for an honest user agent, from the dev machine and the VPS), Mojeek, Bing, Yahoo, Ecosia, Qwant, Startpage and Brave's own search pages (robots.txt disallows them), Yep (Cloudflare block), Marginalia (the shared public key is for experiments and spent daily; other keys are non-commercial or paid).
- **Alerts.** Operator alerts are emailed through the Day3 API (`DAY3_API_KEY`, `ALERT_EMAIL_TO`, `ALERT_EMAIL_FROM`), each key at most once an hour (`alerts_sent`). Without a key they are only logged. Alerts: a source refusing us, and Brave spend this calendar month passing 80% and 100% of `BRAVE_MONTHLY_BUDGET_USD` (requests counted in `source_requests` times `BRAVE_COST_PER_1000_USD`). `cli alert test --prod` sends a test.
- **Free name lookup.** Before a `domains` search pays for a company name, and before a `local` search pays for a place without a website, the name is tried on three free routes (`src/leads/sources/resolve-name.ts`), and the paid search is asked only when none is sure. Known: a company of the same name (legal words such as ApS and Inc ignored) that a past search found and the crawl reached, when OpenStreetMap listed its website (not a place whose website a lookup found) or its domain holds the name, and for a place when its address names the place's town; rows that disagree resolve to the one under the country's TLD, else to nothing. Guess: domains made from the name, run together and hyphenated, under the country's TLD first and then .com, .net, .io, .co and .org, at most 6 DNS lookups and 2 homepage fetches per name, fetched like the crawl (robots.txt, one request per second per host, `nvokebot`). A guess counts when its homepage is not parked or for sale, does not land on a platform or a parking host, and carries the name as its brand (a title part, `og:site_name`, a logo, the copyright line; a one word name must be a title part of its own), and for a place when the page names the town. Names of only generic words or under 4 letters are not guessed. Wikidata: the official website (P856) of the one item whose label is the name, only when the name's distinctive words run to 6 letters or more, never for people, bands or works, and only when the website holds the name; one request a second, paused 10 minutes after a refusal. Names a free route found are stored with source `known`, `guess` or `wikidata`, cost nothing, and do not count toward `MAX_PLACE_LOOKUPS`. Places keep source `osm`, and a place whose website a lookup found (free or Brave) carries the route in its `source_ref` (`node/42#guess`), so the known route never takes it as the map's word. A `local` search tries at most 50 places on the free routes (`MAX_FREE_PLACE_LOOKUPS`) and starts none after 2 minutes (`FREE_LOOKUP_BUDGET_MS`). Each search logs how many names each route resolved, how many the paid search found and how many stayed unresolved.
- **Names.** A `domains` search pays only for names: one request each, none for domains, and none for a name looked up in the last 7 days. Its requests count toward the Brave budget like `web`.
- **Places.** A `local` search pays for places that list no website only when OpenStreetMap's places with a website fall short of the limit: one request per place, at most 50 per search (25 US cents), none for a place looked up in the last 7 days. They count toward the Brave budget like `web`.
- **Measure.** Each search counts its paid requests (`source_requests`) and pages served from the cache (`source_cache_hits`). `cli stats --days 30 --prod` on the VPS prints them per kind next to valid emails, with valid emails per paid request.
