# Web app (nvoke.run/app)

The front door. A person signs up at `/sign-up` (Clerk) and lands in `/app`, with nothing to install. Same account, plans, quotas and API as the desktop app; the browser calls `/v1` with the Clerk session JWT.

- **Searches** (`/app`): the list with status, counters and live progress (polled every 2 seconds while one runs). The website read sits at the top like a search: running while nvoke reads the site, then the site's name with how many searches it planned, opening `/app/website`. The first visit (no searches) offers one action, "Start from your website", with the four kinds by hand below it.
- **New search** (`/app/new`): always a blank "Start from your website" field (see [Site profile](site-profile.md)), even with a profile on file or a read running. A read started there plays out and then opens `/app/website`.
- **Your website** (`/app/website`): the read running, or the profile on file with its suggestions (Read again, Another site, which goes to New search, Edit); Start on a suggestion runs it like the form. `/app/new?manual=1` or `?kind=` opens the desktop's sentence form for `local`, `web`, `launches` and `domains` (paste a list), with a link back.
- **Results** (`/app/searches/:id`): overview numbers and progress, companies with their emails, generic or personal, and a verification badge per address (valid, catch-all, risky, invalid, unknown, or checking). Filter by text, verification and kind; export the CSV with the same filters (the export notice first); stop, run again, delete. Search more opens the sentence form inline, prefilled with the latest run and its kind locked, and adds what it finds to the same list ([pipeline](pipeline.md) step 6); a search that ended short of its limit invites it. Under the title, a search with several runs lists each with what it added. Sites that refuse our servers point to nvoke Desktop, which can read them locally.
- **Drops** (`/app/drops`, `/app/drops/new`, `/app/drops/:id`): the drops (see [Drops](drops.md)) as a list with each one's state, next run and companies delivered, under a display of the feed's week per source. New drop and a drop's page share the desktop's sentence form (keyword, sources, a limit a day, name) with a display that reads it back. A drop's page adds Check now, Pause or Resume and Delete, and lists its runs (its searches of kind `drop`, from `GET /v1/searches`), each opening its results. The list polls while a run is due; the searches list's own polling shows a run delivering. Drop notifications stay in nvoke Desktop.
- **Account** (`/app/account`): usage meter, plan with Upgrade or Change plan, a "Get nvoke Desktop" card (the power tools), API keys (create, shown once, revoke) with the MCP URL, sign out.
- **Billing** (`/app/billing`): the plan picker and Clerk Billing checkout from `/desktop/billing`.
- **Quota.** From 80% of the allowance every screen shows the month's remaining emails and an Upgrade link; at 100% it says searches stop at the limit. A refused search (403 `quota_exceeded`) and a search stopped by the allowance both offer Upgrade.

Webhooks, drop notifications, the local render crawl, quick search, grab, CSV drop and the local copy stay in nvoke Desktop (and the API).
